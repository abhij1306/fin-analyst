# Decisions: D2 (PRs #69, #70, #71)

Written after the fact from the PR bodies and the code. Builder readings, not owner decisions.

## PR #69: Ledger Vouchers need their period's trial balance first (E811)

- **Decision:** Ingesting Ledger Vouchers before the period's trial balance is refused.
- **Why:** The trial balance says which ledgers are parties, and Tally leaves zero-balance ledgers out of it. Without it fin cannot mask party names in the vouchers.
- **Alternatives considered:** Load vouchers first and mask afterwards (names would be stored unmasked meanwhile); mask every ledger (loses the party/non-party distinction).
- **Where in code:** src/fin/diligence/sources.py: ingest_source
- **How to change it:** Drop the E811 check and mask in a later pass.

## PR #69: A Ledger Vouchers ledger not in its trial balance is masked as LEDG-0001

- **Decision:** Such a ledger gets a `LEDG-` token.
- **Why:** Fin cannot tell whether it is a party; over-masking is safer than leaking a name.
- **Alternatives considered:** Store it as filed; ask the user.
- **Where in code:** src/fin/diligence/sources.py: _load_lv; mask.py
- **How to change it:** Store the name as filed in `_load_lv` when the ledger is not a party.

## PR #69: A masked value keeps its first token

- **Decision:** A name first masked as LEDG keeps that token if a later file finds it under a party group (Tally ledger names are unique).
- **Why:** One ledger must not have two tokens across years.
- **Alternatives considered:** Re-token by kind (breaks joins across files).
- **Where in code:** src/fin/diligence/mask.py: Masker.token
- **How to change it:** Make the token depend on kind and migrate existing rows.

## PR #69: Column profiles, not code, describe a layout

- **Decision:** A TOML profile gives header text, date format, skip rows, group rows (bold), nesting (indent), block field and party groups. An unknown layout is E807 listing title and header lines (never data rows, known names replaced).
- **Why:** Real exports may differ; a profile change is cheaper than a code change. Extraction stays simple.
- **Alternatives considered:** Per-layout parsers; layout heuristics.
- **Where in code:** src/fin/extract/ledger.py, profiles.py; templates/profiles/*.toml
- **How to change it:** Edit or add a profile (docs/CUSTOMISING.md: Add a column profile).

## PR #69: A date in another format is never dropped

- **Decision:** An undated row with amounts that the profile does not skip is E204; a Ledger Vouchers file with no voucher line is E204.
- **Why:** Silently dropping lines would change figures.
- **Alternatives considered:** Skip undated rows.
- **Where in code:** src/fin/diligence/tally.py: ledger_entries
- **How to change it:** Add the row's name to [rows] skip in the profile.

## PR #69: Group sum differences are findings; group-only trial balance is refused

- **Decision:** A group not equal to its ledgers is a finding (`tb_group_sum`), rows kept as filed. A trial balance with no ledger rows is E809.
- **Why:** What a company filed that does not add up is a finding, not a failure. Group rows alone cannot map to accounts.
- **Alternatives considered:** Fail the load on a difference.
- **Where in code:** src/fin/diligence/tally.py: group_sum_findings, trial_balance_rows
- **How to change it:** Raise instead of recording a finding.

## PR #69: Period must be one full year; a later file supersedes

- **Decision:** The export period must be a year of the engagement (E808). A later file of the same kind and period supersedes the earlier one and its findings; the same sha256 is always E105.
- **Why:** Matches how documents behave.
- **Alternatives considered:** Keep both files.
- **Where in code:** src/fin/diligence/sources.py: _supersede
- **How to change it:** Remove the supersede step.

## PR #69: fin sql cannot read names or write source tables

- **Decision:** SQL naming `mask_values`, or calling `query`, `query_table`, `read_duckdb`, is E810; writes to source tables are E806.
- **Why:** Guards against reading names or undoing masking by accident. It is not a sandbox.
- **Alternatives considered:** Encrypt `mask_values`.
- **Where in code:** src/fin/query/run.py: refuse_masked; src/fin/query/write.py
- **How to change it:** Edit the regexes.

## PR #70: Split cli.py into a package

- **Decision:** `src/fin/cli/` with core, init, ingest, findings, statements, data (later reconcile). `fin.cli:app` still resolves.
- **Why:** cli.py was over the 6,000-token limit. Code moved verbatim; the shared checks lost their leading underscore.
- **Alternatives considered:** Compress the file (not allowed by the size rule).
- **Where in code:** src/fin/cli/__init__.py
- **How to change it:** Add a module and import it in `__init__.py`; import order sets the order in `fin --help`.

## PR #71: G1 trial balance checks apply only once an engagement has a TB, Ledger Vouchers or stub (builder reading)

- **Decision:** With none of them, G1 keeps its D1 checklist and shows one passing line saying the checks are not active.
- **Why:** The plan says D2 adds a TB and LV per period; making them mandatory would break every D1 engagement that approves G1 on statements alone. A reading, not an owner decision.
- **Alternatives considered:** Mandatory everywhere.
- **Where in code:** src/fin/diligence/tb_checks.py: checklist
- **How to change it:** Remove the early return when there are no files and no stub.

## PR #71: Current-year profit from income and expense ledgers counts into other equity in tb_vs_statements (builder reading)

- **Decision:** P&L ledgers also roll into `other_equity`.
- **Why:** Tally lists the year's income and expenses beside the opening Profit & Loss A/c, while the balance sheet's other equity includes the year's profit. Without it every year raises a false query on other equity.
- **Alternatives considered:** Compare P&L only; ask the user to map a profit ledger.
- **Where in code:** src/fin/diligence/recon.py: RETAINED, _roll_up
- **How to change it:** Stop adding profit ledgers in `_roll_up`.

## PR #71: Existing G1 approvals reopen (builder reading)

- **Decision:** G1's hash now includes source files, ledger mappings and the latest reconciliations, so an earlier approval reopens.
- **Why:** The data under the gate changed; no released data exists and there are no migrations by owner rule.
- **Alternatives considered:** Version the hash.
- **Where in code:** src/fin/diligence/tb_checks.py: inputs
- **How to change it:** Drop a key from `inputs`.

## PR #71: Ledger mappings and presence

- **Decision:** Only confirmed ledger mappings count. fin never confirms. Presence in TB or Ledger Vouchers is computed from the loaded files, not stored.
- **Why:** Stored columns could go stale.
- **Alternatives considered:** A presence column.
- **Where in code:** src/fin/diligence/ledgers.py: read
- **How to change it:** Add the column to ledger_accounts and fill it on load.

## PR #71: Reconciliation queries

- **Decision:** Differences at or above the engagement threshold get a neutral draft query with the two amounts. No query while any ledger is unmapped. A re-run reuses a query only when the account and both amounts match and it is not withdrawn. The stub cannot be reconciled (E812).
- **Why:** The difference may be fin's own mapping gap; the stub has no audited statement.
- **Alternatives considered:** Query every difference.
- **Where in code:** src/fin/diligence/recon.py: _reconcile, _earlier_query
- **How to change it:** Change the threshold test or the reuse rule.
