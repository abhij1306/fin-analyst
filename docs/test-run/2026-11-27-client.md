# First client run, 2026-11-27

What the first run on a client's own documents showed. Source: the run logs, the install log and the Claude action log
the client sent back (kept outside the repo; `/client/` is ignored). Names, figures and file names are left out. Each
observation points to the spec that answers it ([specs/](../specs/README.md)).

The `product.md` that came back is this repo's copy with two lines added (observation 5). The observations below
are read from the logs and are readings until the owner or the client confirms them. On 2026-11-28 the client also
sent, through the owner, what their Claude named as missing; it is the last section.

## The session

- One Mac (Apple Silicon), Claude Code in the desktop app, one company, about one hour from install to an adjusted
  EBITDA bridge.
- 82 `fin` runs: 25 `sql`, 8 `adjust propose`, 7 `ingest`, 7 `map accounts`, plus status, review, findings,
  engagement and gate commands. Every command took under 3 seconds.
- Never run: `fin ui`, `fin report`, `fin dashboard`, `fin statements`, `fin verify`, `fin eval`. The golden
  evaluation in [client-handoff.md](../client-handoff.md) did not happen.

## Observations

### Install

1. **Three attempts.** `brew bundle` failed on the Quarto cask, which needs `sudo` and had no terminal to ask for a
   password. `install.sh` retried three times, waiting 60 seconds each, and ended with "check the network". The
   network was fine. → SPEC-12
2. On the second attempt uv picked an Intel Python 3.9 on the PATH and failed with "Bad CPU type". → SPEC-12
3. The repo was installed inside the desktop app's temporary workspace folder (a path with spaces), not a folder the
   user chose. → SPEC-12

### Ingest

4. **No document loaded without a Claude reading.** 12 files were given; `fin ingest` failed all 12:

   | Code | Files | Message |
   |---|---|---|
   | E203 | 5 (3 PDF, 2 Excel) | no unit line such as "₹ in Lakhs" |
   | E201 | 3 PDF | no statement tables with values found |
   | E104 | 3 PDF | no text layer (scans) |
   | E103 | 1 | `.xls` files are not supported |

   A retry of one Excel file then failed with E204 (values with no label). No PDF add-on was chosen (`parser = "none"`).
   Four documents were then loaded through `fin ingest --reading`: 247 figures, all read by Claude. Eight files were
   never loaded. This contradicts the working assumption in `CLAUDE.md` that the documents are well formatted and
   extraction is not a problem to solve. → SPEC-03, SPEC-04
5. The client's Claude changed the unit reader locally so that "All amounts in INR, unless otherwise stated" means
   rupees, and added two lines to `product.md` for it. The change is not in this repo. → SPEC-01
6. A user sees none of this without reading terminal output: which files failed, why, and what to do next. → SPEC-03

### Mapping

7. 40 labels had no dictionary mapping, 29 of them cash-flow lines (working-capital movements, the three activity
   totals, opening and closing cash). → SPEC-05
8. All 40 proposals were confirmed in one command, including three at confidence 0.5 and one at 0.75. → SPEC-05
9. Four subtotal findings (E402) came from one mapping, not from the company's figures. Clearing them took
   `fin map set` and a forced re-ingest of the same reading. → SPEC-05
10. The cash-flow check and the cross-document checks never ran ("no confirmed cash figure", "no other loaded
    document"); the user was not told what would make them run. → SPEC-05

### Questions and presentation

11. **Units and layout.** The user asked for every figure in INR million, laid out like a diligence databook: line
    items as rows, fiscal years as columns, whole numbers, negatives in brackets, "% of revenue" columns. fin stores
    rupees and has no display setting, so Claude divided by a million in each query and saved the preference in its
    own memory, where fin, the UI and the reports cannot see it. → SPEC-06
12. **Guessed column names.** 7 of 25 `fin sql` runs failed with E504 on a column that does not exist
    (`document_id`, `source_file`, `source_confirmed`, `input_account`, `label`). Claude then read the schema
    files in `src/`. → SPEC-07
13. One `fin sql --evidence` run ended with an unexpected `TypeError` and no error code. → SPEC-01
14. The first question (revenue to cash conversion) has no metric in the catalogue; the ratio was written by hand
    and is not saved anywhere. → SPEC-07
15. The user asked for the three statements "reported and after diligence". fin has an adjusted EBITDA bridge but no
    adjusted statements. → SPEC-09

### Diligence

16. **Third-party databooks.** The user holds a banker's databook and an advisor's FDD databook for the same company
    and compares fin against them. Claude opened them with ad-hoc Python outside fin; one difference it noticed
    (an operating cash flow figure) was reported in chat and recorded nowhere. → SPEC-10
17. Eight adjustments were typed from a "walk" sheet as eight `fin adjust propose` calls in a shell loop. The first
    two attempts failed: a negative amount after an option (`--revenue-effect -1000000`) is read as a flag. → SPEC-01,
    SPEC-09
18. `fin adjust list` and `fin query list` fail with E803 when no engagement is open, instead of saying there is
    nothing to list. → SPEC-01
19. **A missing line stopped the bridge.** The P&L has no finance cost line, so EBITDA could not be computed. On the
    user's instruction Claude wrote three zero-value rows straight into `raw_values` and `facts` with
    `fin sql --write`, an invented run id and `read_by = 'claude'`. fin has no command for a figure the user states.
    → SPEC-08
20. `fin adjust accept` was refused (E801) until gates G1 and G2 were approved; every checklist item already passed.
    The approval prompt worked as designed. It took the user about six minutes and two more questions. → SPEC-09

### What worked

- Every data change went through `fin` and is in the run log, including the two that should not have been possible
  that way (19).
- The gate hook asked the user before each approval.
- After the adjustments were accepted, fin's adjusted EBITDA matched the user's own walk in every year.

## What the client asked for (2026-11-28)

Written by the client's Claude and passed on by the owner. It says the loaders, ledger mapping, reconciliations and
query grouping of the diligence build are there, and names three missing pieces, to be built in this order:

1. **Data-room intake.** One command that walks a folder, unpacks archives, drops duplicate files, says what kind
   each file is, shows that before loading, loads what is approved in one run, and lists what it cannot use and why.
   → SPEC-13
2. **Rebuilt statements.** The P&L and balance sheet built from the trial balance through the confirmed ledger
   mappings for every year, and a cash flow derived from the change in balances, shown as reported, rebuilt and
   difference in the client's unit and layout. → SPEC-14, SPEC-06
3. **One list of all differences**, from the headline figure to the account, the party and the transaction, each
   with both sources, the amounts and its query; the ladder ends at the adviser's databook, loaded as a reference.
   → SPEC-15, SPEC-10

Risks the client named: the register loader's column headings are synthetic and need mapping once against the real
export; rebuilt figures need a ledger-level trial balance for each year; one year's ledger arrives as PDF.
