Run by Claude Code as the client's agent would, from `docs/EVAL.md`, the README and the slash commands, in a scratch
data folder (`FIN_DATA_DIR`, never `~/FinAnalysis`), on the committed fixtures (`tests/fixtures/sample-financials/`)
and files written with the test generators (`tests/fixtures/*` helpers) for one diligence company, `acme`, with
planted differences. Windows host, so the console was set to UTF-8 (`PYTHONUTF8=1`; macOS is fin's only target).

Result key: PASS (as the docs say), FAIL (a bug, fixed in this PR with a regression test), CONFUSING (works, but a
reader is misled; fixed or recorded). Decisions: `docs/decisions/test-run.md`.

| Step | What happened | Result |
| --- | --- | --- |
| 5.1 | `bank_vs_invoices` fx line: the USD 2,000 receipt for INV-2005 was never booked; fin took the customer's only Receipt voucher within `fx_window_days` (Rs 2,00,000 into the INR account, another receipt) and showed a false fx gain of 40,000 where none was planted. Cause: the lookup checked customer and date only, never whether the voucher's rupees fit the receipt (not the window, the tie-break or reuse). The output also did not show the voucher and printed "None" for a missing amount | FAIL |
| 5.2 | A cash ledger mapped to `cash` while the statements use `cash_and_bank_balances` gave four large spurious draft queries. After the remap the new run no longer had those lines, but nothing said the four drafts were orphaned | FAIL |

Fix 5.1: a booked voucher counts only at a rate within 10% of the invoice's; one further off is named in a "no booked
value" note and no fx line is made; an fx line names its voucher; missing amounts print "-" (`bank_lines.py`,
`bank.py`); test `test_diligence_bank_match.py::test_a_booked_receipt_at_another_receipts_amount_is_not_taken_as_the_rupee_value`.
After the fix the run shows INV-2005 matched with "no booked value" naming the voucher it set aside.
Fix 5.2: the run lists stale drafts and how to withdraw them; fin withdraws nothing
(`recon.py: _stale_drafts`); test `test_diligence_recon.py::test_a_draft_whose_difference_is_gone_is_listed_stale_and_never_withdrawn`;
the /diligence skill tells Claude to propose the account the statements use.

## EVAL CANDIDATES

What to check on real documents, what a wrong result looks like, and which golden check catches it.

| # | Check on real documents | A wrong result looks like | Golden check |
| --- | --- | --- | --- |
| 1 | EBITDA for a company whose statement has no finance cost or depreciation line | EBITDA blank in the metrics and report | `metric` EBITDA per period (a person computes it from the statement) |
| 2 | Cash ledgers map to the account the statements use | large `tb_vs_statements` drafts on cash with equal and opposite lines | `tb_vs_statements` lines for cash and bank |
| 3 | The fx line uses the right booked receipt (Tally books the foreign receipt with its own voucher) | an fx difference on an invoice paid at the booked rate, one equal to another receipt's amount, or "no booked value" where the books do hold the receipt (a real rate move over 10%) | `fx_line` per invoice, from the voucher a person finds |
| 4 | Recast months add to the line and are even | a month off by paise, a period total off | `recast_revenue`, `recast_difference` per period |
| 5 | Queries from bank findings carry an engagement period | a query absent from `fin query list --period` or G1/G2 | `query_issue` with its period |
| 6 | Related codes in the bundle point at the right document | a fail listed with codes from another document of the same period | read by hand in the bundle; no golden kind (statement checks relate codes by period) |
| 7 | A misread digit in a large figure | relative difference shown as 0 | any `statement` check |
| 8 | `query_issue` sign | a credit-side query failing at the right size | `query_issue` |
